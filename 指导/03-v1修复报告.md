# 03 v1 修复报告：改了什么、为什么、怎么自证

> 目的：你按"v1 当课本"学习时，这份报告告诉你 v1 里哪些地方是**错的或缺的**、
> v2 怎么修的、以及每一处你如何用 10-30 分钟亲手验证——把"AI 修的"变成
> "我能推导、能复现、能防守的"。
> 完整逐条变更清单（20 项）见根目录 `IMPROVEMENTS.md`；本报告按**严重度**
> 重组，只讲"修"，不讲"新增功能"的部分从简。

## A 类：正确性 bug（v1 里是错的，学习时必须绕开）

### A1 nDCG 的 IDCG 实现错误（v1 本地 eval/metrics.py）

- **错在哪**：理想 DCG 从"已检索到的 gains 重排"计算——只要命中 ≥1 条，
  nDCG 恒为满分，漏检目标不进分母。它退化成了 Recall 的另一种写法，失去
  排序度量意义。
- **v1 原代码 vs v2 修复**：

```python
# v1（错误）：ideal_gains 来自已检索结果自身
gains = [1.0 if rid in golden_set else 0.0 for rid in retrieved_ids[:k]]
ideal_gains = sorted(gains, reverse=True)                 # ← 病灶
idcg = sum(g / np.log2(i + 2) for i, g in enumerate(ideal_gains))

# v2（正确）：IDCG 按全部相关目标数计算
ideal_hit_count = min(len(golden_set), k)
idcg = sum(1.0 / np.log2(i + 2) for i in range(ideal_hit_count))
```

- **影响**：多答案 query 的 nDCG 全部虚高；v1 口径的 nDCG 一律不可引用。
- **自证练习**：手算"2 个答案、命中 1 个排第一"：DCG=1/log2(2)=1；
  错版 IDCG=1 → nDCG=1.0；对版 IDCG=1/log2(2)+1/log2(3)≈1.63 → nDCG≈0.61。
  再把 v2 的 `tests/test_metrics.py::test_idcg_uses_full_golden_size_not_retrieved_gains`
  指向 v1 本地 metrics 跑一次，亲眼看红。

### A2 Reranker 原地修改调用方数据（v1 src/reranker.py）

- **错在哪**：直接往传入的候选 dict 写 `rerank_score`，污染 State 里的
  `retrieved_docs`；同进程多配置评测时前一配置的分数残留进下一配置（顺序依赖
  的伪随机）。
- **对照**：

```python
# v1：for doc, score in zip(docs, scores): doc["rerank_score"] = float(score)
# v2：scored_docs = [doc.copy() for doc in docs]   # 先浅拷贝再打分
```

- **自证练习**：读 v1 `rerank()`，回答"为什么 v1 的 dual_query benchmark 里
  必须写 `rerank_input = [doc.copy() for doc in candidates]` 防御"（答案：
  就是在绕这个坑，v1 作者自己都被迫防御了）。

### A3 评测自命中污染（v1 本地 eval/run_eval.py）

- **错在哪**：评测 query 自身在索引里，检索第一名几乎总是自己，占名额且把
  真答案整体后推；v1 不剔除。
- **v2 修复**：检索 `top_k+1` 条后剔除自身 id 再截断（`_exclude_self`）。
- **自证练习**：临时注释 v2 的 `_exclude_self` 跑 10 条，数一数第一名是
  自己的比例。

### A4 Ground Truth 不可达（v1 golden set 构建）

- **错在哪**：34.4%（4,505/13,104）的 duplicate query 的目标 issue 不在索引
  （被清洗过滤或数据集缺失），v1 全部计为检索失败——所有指标被系统性低估
  约 1/3。
- **v2 修复**：用 bm25.pkl 的 id 全集逐条校验，剔除不可达与自引用目标。
- **自证练习**：跑 `python scripts/build_eval_assets.py` 看 build_stats；
  从日志挑 2 个被剔除的 target id，去索引里搜确认真不在。

### A5 评测集划分泄漏（v1 随机 query 级 80/20）

- **错在哪**：同一 duplicate family 的成员被拆进 eval/test 两侧（调参见过
  A→B，测试又考 B→A），test 指标虚高。
- **v2 修复**：并查集把 query 与答案连成 3,333 个 family，按 family 整体
  划分并按 project 分层。
- **自证练习**：手画 a→b、b→c，解释为什么"成对处理"漏传递闭包、必须并查集。

### A6 golden set 构建漏 normalize（v1 本地）

- **错在哪**：`clean(load_data())` 直接清洗原始数据，跳过字段标准化——评测
  query 的文本形态与建索引链路不一致。
- **v2 修复**：统一为 `clean([normalize(x) for x in load_data()])`。

### A7 凭据与配置两处安全/可靠性问题

- **`.env.example` 提交了真实有效的 DeepSeek key**（已进 git 历史；2026-07-26
  实测该 key 认证 200、余额 0）。v2 改占位符 + 真 key 移入 gitignored .env。
  **⚠️ 你仍需去 DeepSeek 平台作废该 key。**
- **`load_dotenv()` 默认不覆盖 shell 残留环境变量**：排查 401 时发现 shell
  里有个失效旧 key（尾号 7b84）压过了 .env。v2 改 `load_dotenv(override=True)`。
- **自证练习**：读报错里 key 尾号 → 对 .env → 对 `echo $DEEPSEEK_API_KEY`，
  复盘这条定位链。

## 一页总结

- **学习 v1 时的"禁区标记"**：A1（nDCG）、A2（原地污染）两处代码不要当范式
  记；A3-A6 属于评测侧，v1 评测代码整体不看（评测只看 v2）。
- **面试价值排序**：A4（34% 故事）> A1（nDCG 手算）> B1（docstore）>
  B4（白名单）> A5（family 划分）——这五个每个都配了自证练习，做完就是
  你自己的东西。
- 数字状态：以上修复的**效果量**（如 docstore 对 rerank 的提升）尚待消融
  跑出（评测/07 清单）；修复本身的**存在性**全部有代码与测试背书。
