# 09 GPT 提问模板（10 个，可直接复制粘贴）

## 📌 项目速览（每个文档都重复，便于单独阅读）

Issue 查重系统：新 issue 提交后，在 106,714 条历史 issue（GitBugs 数据集，8 个开源项目）里找重复，输出 duplicate / similar / new 三分类 + 置信度 + 相关 issue 编号 + 判断理由。在线流程是 LangGraph 四节点：LLM 改写 query → 双路混合检索（BM25 + 向量各 Top-30，双层 RRF 融合，docstore 补齐正文）→ Cross-Encoder 精排 Top-5 → LLM 决策 + 程序级校验；置信度 < 0.7 且未超 2 次重试时带诊断回环重写。技术栈：Python、LangGraph、DeepSeek、ChromaDB（all-MiniLM-L6-v2，384 维）、rank-bm25、bge-reranker-base、FastAPI。

> **通用用法**：每个模板使用前，先在同一条消息里粘贴「📌 项目速览」+ 模板注明的
> 对应文档全文，再贴模板本身。`【】`里的内容替换成你的目标。文档编号速查：
> 01a/01b 架构、02a/02b 链路、03a/03b 决策、04a/04b 问答、05a/05b 故事、
> 06a/06b 评估、07 缺陷路线、08 术语。

## 模板 1：苏格拉底式检验（检验我是否真懂某个模块）

> 使用前粘贴：项目速览 + 该模块对应文档（如检验 RRF → 03a；检验校验层 → 03b）

```
你是一位严格但友善的技术导师。基于我提供的项目文档，用苏格拉底式提问检验我是否
真正理解【RRF 融合 / docstore / 决策校验层 / chunk 策略】。

规则：
1. 一次只问一个问题，从"是什么"开始，逐层深入到"为什么这样设计""什么情况下会失效"。
2. 我回答后，先指出我回答中的错误或含糊之处（对照文档事实），再问下一个。
3. 我连续答对 3 个深层问题后，出一个文档里没有直接答案、需要推理的迁移问题。
4. 全程不要直接把答案讲给我，引导我自己说出来。
现在开始第一个问题。
```

## 模板 2：模拟面试官（完整面试演练）

> 使用前粘贴：项目速览 + 04a + 04b（可加 05a 的逐字稿）

```
你扮演一位大厂后端/算法岗面试官，正在面试我的这个 RAG 项目。基于我提供的文档：

1. 先让我做 2 分钟项目介绍（我会打字输入，请容忍口语）。
2. 然后进行 15 轮问答：从基础问起，每轮根据我上一个回答里的薄弱点追问，
   风格是"抓住一个点往深挖"而不是换话题。
3. 至少覆盖：检索方案选型、RRF、评估方法、一个失败案例、扩展性压力题。
4. 我打 "END" 后，给我一份面试反馈：哪些回答加分、哪些回答会被扣分、
   每个薄弱点对应该复习哪份文档的哪一节。
现在开始。
```

## 模板 3：把某段实现讲得更细（代码走读）

> 使用前粘贴：项目速览 + 含该代码块的文档（02a/02b/03a/03b 内嵌了全部核心源码）

```
下面文档里有一段【search_queries 外层 RRF / decision_node 校验 / chunk_issue】
的源码。请你：
1. 逐行讲解这段代码在做什么，用"输入是什么→这行把它变成什么"的方式；
2. 指出其中 3 个容易被忽略的细节（比如排序稳定性、copy 语义、边界条件），
   解释如果没有这个细节会出什么 bug；
3. 给一个具体的输入例子（构造 2-3 条假数据），手动推演这段代码的完整执行过程
   和中间变量的值；
4. 最后出 2 道"改代码"思考题（比如：如果要求 X，这段代码要改哪里）。
```

## 模板 4：实现时卡住了怎么问（debug 求助）

> 使用前粘贴：项目速览 + 相关模块文档；再附上你的报错/代码片段

```
我在复现/修改这个项目的【模块名】时卡住了。背景文档如上。

我的目标：【想实现什么】
我做了什么：【贴代码或步骤】
实际现象：【贴完整报错或错误输出，不要截断】
我已排除：【已经试过什么】

请你：
1. 先列出 3 个最可能的原因，按概率排序，每个说明"如果是它，现象应该是什么"；
2. 给出每个原因对应的最小验证方法（一条命令或几行代码）；
3. 不要一上来就给完整解决方案，先帮我定位；我反馈验证结果后再继续。
```

## 模板 5：备选方案对比（检验设计决策理解）

> 使用前粘贴：项目速览 + 03a 或 03b 中对应决策

```
文档里说这个项目选择了【RRF 而不是加权融合 / 独立 docstore 而不是塞进 BM25 /
LLM 决策而不是分数阈值】。请你扮演一个持反对意见的资深工程师：

1. 先尽力为"被放弃的备选方案"辩护，给出 3 个支持它的强论据；
2. 然后我来反驳你（基于文档里的权衡理由），你评判我的反驳是否站得住；
3. 最后你给出裁决：在什么条件下原方案确实应该换成备选方案（给出具体的
   数据规模/团队/延迟条件），让我理解"没有绝对正确的选型，只有条件"。
```

## 模板 6：给我出题（主动检测知识盲区）

> 使用前粘贴：项目速览 + 你想被考的 1-2 份文档

```
基于这份文档出 10 道检测题考我：
- 3 道事实题（文档里有明确答案）
- 4 道理解题（需要把文档里两处信息连起来才能答）
- 3 道迁移题（文档没直接讲，但用文档里的原理能推出来）

规则：一次出完 10 道题（不给答案）；我作答后，逐题批改打分（每题 10 分），
指出每道题我丢分的具体原因，最后汇总我的三个最薄弱知识点和对应复习建议。
```

## 模板 7：复述纠错（费曼学习法）

> 使用前粘贴：项目速览 + 对应文档

```
我现在用自己的话复述【一条 query 的完整生命周期 / 评估体系的四层修复 /
docstore 的设计】，你对照文档帮我纠错：

我的复述：【打字复述，不看文档】

请你：
1. 列出我复述中的事实错误（说错的数字、顺序、机制），逐条给出文档里的正确版本；
2. 列出我遗漏的关键点，按重要性排序；
3. 列出我说得含糊、面试时会被追问的表述，示范怎么说更精确；
4. 给我的复述打一个 0-100 的完整度分数。
```

## 模板 8：缺陷追问模拟（练"最大缺点"类问题）

> 使用前粘贴：项目速览 + 07 + 06b

```
你扮演一位喜欢挑刺的面试官。我会说出这个项目的一个已知缺陷，你的任务是连续
追问 4 层，逼我说清楚：
第 1 层：这个缺陷的技术根因是什么？
第 2 层：它对线上/评估的具体影响有多大，怎么量化？
第 3 层：为什么当时没修？（考察权衡意识，不接受"没时间"这种回答）
第 4 层：修复方案的具体步骤和成本？
我每答一层你先点评（严格些），再问下一层。我先说缺陷：【时间穿越 / BM25 延迟 /
置信度未校准】。
```

### ✅ 自测（模板使用）

1. 为什么每个模板都要求"先粘贴项目速览 + 对应文档"？只贴模板会发生什么？
2. 模板 1（苏格拉底）和模板 6（出题）分别适合学习的哪个阶段？
3. 用模板 4 求助时，"实际现象"一栏为什么强调贴完整报错不要截断？

---

## 自测答案

<details>
<summary>答案</summary>

1. GPT 看不到代码库，文档是它唯一的事实来源；只贴模板它会基于通用知识编造
   "一个典型 RAG 项目"的答案，细节（数字、参数、设计理由）全是幻觉，
   检验和讲解都会失真。
2. 模板 1 适合"学完一个模块后"的深度检验（暴露理解含糊处）；模板 6 适合
   "复习阶段"的广度扫盲（快速定位遗忘点和盲区）。顺序建议：先 6 找盲区，
   再 1 逐个击破，最后 2 全真模拟。
3. 报错的关键信息经常在被截掉的部分（本项目真实案例：401 报错里的 key 尾号
   直接指向了 shell 残留变量这个根因）；截断后 GPT 只能猜，定位效率大幅下降。
</details>
