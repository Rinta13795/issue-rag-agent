# 对话中的只读代码工具

直接在原来的对话中提要求。没有新的项目入口、连接操作或权限开关。

## 用法

- 当前资料仓库：“读一下这个仓库的检索实现。”Agent 直接读取该 GitHub 仓库的文件树和源码。
- 其他公开仓库：“看看 owner/repo 是怎么处理缓存的。”也可以提供 GitHub 仓库链接。无需切换当前资料仓库，也无需为参考仓库同步 Issue 索引。
- 本地代码：“读 /absolute/path/to/project 的检索模块。”Agent 将路径作为工具参数直接读取；省略本地路径时，默认读取服务所在项目。
- 寻找参考：“根据刚才的问题找其他公开实现。”Agent 可以搜索仓库，再定点读取相关源码。

读取结果带文件、行号和来源；公开仓库源码按文件树返回的固定 commit 读取。本地代码与外部参考不会冒充当前资料仓库的历史修复。

## 找灵感与反馈

要求改进 idea 时，Agent 应先读取当前源码和测试，必要时主动查相关公开仓库，再提供少量有证据的可选方向。旧文档只作背景，不能据此断言代码还没实现，也不能把历史延迟、余额当成当前状态。

否定一个方案后，继续寻找改进方向的目标仍然保留：排除该方案，继续调查其他实现。只有“这个过期了”等反馈确实存在意图歧义时，才使用现有提问选项区分“核实现在的实现”和“换方向找新 idea”，而不是泛问下一步要做什么。

模型上下文还包含保留的工具活动统计，区分搜索候选、Issue/PR 原文读取、本地文件与外部代码读取。这些统计截至本轮开始，只覆盖最近保留的工具记录，不代表全历史阅读量。

## 工具

- `list_project_files`、`search_project_code`、`read_project_file`：本地源码读取，`project_path` 可指定本地项目绝对路径。
- `search_reference_repositories`：寻找公开 GitHub 仓库。
- `read_repository_tree`、`read_repository_file`：读取任意公开 GitHub 仓库；`repository` 支持 `owner/repo` 或仓库链接，省略时使用当前资料仓库。
- 既有 `read_issue/read_pr/search_prs` 也支持显式参考仓库。

## 范围

代码工具只有读取、列目录和搜索，没有源码修改、文件创建、项目检查、命令执行或 Git 写入功能。原有 Issue 草稿流程保持原样。

本地文件须为项目目录内普通 UTF-8 文本，拒绝越界、凭据和软链接；单文件最多 250 KB，单次最多 300 行。目录列表、搜索和远端文件树有结果上限，大项目需要缩小调查范围。GitHub 读取限可访问的公开仓库，凭据错误、限流和不可访问的仓库都会返回失败。

GitHub HTTPS传输失败且本机已安装 `gh` 时，可沿用本机网络配置，通过客户端的固定 GET 请求读取同一 GitHub API。正常的403/404/429拒绝不会改走备用通道；未安装客户端或备用读取失败时仍报告失败，不提供任意命令执行接口。

普通 Issue 调查保持 6 次模型、10 次工具预算；使用代码工具后扩大为 12 次模型、24 次工具，最后一次用于总结。远端固定版本结果可在当轮缓存，本地源码每次重新读取。
