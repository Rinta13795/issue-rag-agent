## 一、入口与 Query 改写（步骤 0-1）

### 步骤 0：入口与初始 State

- **输入**：一段 issue 文本（str）。
- **处理**：`run_agent` 取进程内缓存的编译图，构造初始 State，其余字段由节点逐步
  写入（节点只返回自己新增的字段，LangGraph 负责 dict 合并：新键加入、旧键覆盖）。
- **输出**：进入第一个节点 `query_analysis`。

```python
# src/agent/graph.py
_COMPILED_GRAPH = None

def get_graph():
    """进程内唯一的已编译 LangGraph；v1 每次 run_agent 都重新构图，v2 缓存。"""
    global _COMPILED_GRAPH
    if _COMPILED_GRAPH is None:
        _COMPILED_GRAPH = build_graph()
    return _COMPILED_GRAPH

def run_agent(issue_text: str) -> dict:
    graph = get_graph()
    initial_state = {"raw_issue": issue_text, "retry_count": 0, "previous_decisions": []}
    final = graph.invoke(initial_state)
    return {  # 只返回对外需要的最终决策字段
        "decision": final["decision"], "confidence": final["confidence"],
        "related_issues": final["related_issues"], "reasoning": final["reasoning"],
        "retry_count": final["retry_count"],
    }
```

def _parse_json(text: str, fallback: dict) -> dict:
    cleaned = text.strip()
    cleaned = re.sub(r"^```(?:json)?\s*", "", cleaned, flags=re.IGNORECASE)  # 剥代码块
    cleaned = re.sub(r"\s*```$", "", cleaned)
    match = re.search(r"\{[\s\S]*\}", cleaned)      # 截取被说明文字包裹的 JSON 对象
    if not match:
        return fallback
    try:
        return json.loads(match.group(0))
    except json.JSONDecodeError:
        return fallback

## 二、双路混合检索（步骤 2）

- **输入**：`rewritten_query`、`raw_issue`、`keywords`、`component`。
- **处理**：改写 query 和原文各跑一遍"Vector + BM25 + 内层 RRF"，两路再做外层 RRF，
  融合后 docstore 补齐空正文候选。
- **输出**：`retrieved_docs`（Top-30，score 为双层 RRF 融合分）。

Retrieval 节点（`src/agent/nodes.py` 节选）：

```python

    queries=[state["rewritten_query"], state["raw_issue"]],   # 改写主路 + 原文兜底路

    bm25_extra_terms=state.get("keywords", []),               # v2：keywords 参与 BM25
```

> 容易说错的点：**两路检索在实现上是顺序调用，不是并发执行**（先 vector 后 bm25，
> 两条 query 也是顺序循环）。"并行"只指逻辑上互不依赖、结果地位对等；瓶颈在 BM25
> 单路本身，并发化收益小（见 02b 耗时表）。

### 2.1 BM25 路（`src/retrievers/bm25_retriever.py`）

```python
def search(self, query, top_k=BM25_TOP_K, extra_terms=None):
    # 查询分词必须复用建索引时的 tokenize（jieba+空格细分+小写），规则一致才能对上词。
    query_tokens = tokenize(query)

    # v2：keywords 追加进 token（同样过 tokenize），等效提升错误码/API 名的词频权重。
    for term in extra_terms or []:
        if isinstance(term, str) and term.strip():
            query_tokens.extend(tokenize(term))

    # issue 粒度索引：get_scores 对全库 106,656 条打分（纯 Python，在线延迟大头）。
    scores = self.bm25.get_scores(query_tokens)
    top_indices = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)[:top_k]

    # v2：过滤 0 分候选——0 分 = query 词一个都没命中，进 RRF 只会挤占配额。
    return [{"id": self.ids[i], "score": float(scores[i])}
            for i in top_indices if float(scores[i]) > BM25_MIN_SCORE]
```

### 2.2 Vector 路（`src/retrievers/vector_retriever.py`）

```python
def search(self, query, top_k=VECTOR_TOP_K, filter_dict=None):
    # Chroma 按 chunk 存储：先多召一倍 chunk（30×2=60），再聚合到 issue 粒度——
    # 因为同一 issue 的多个 chunk 会占多个名额，不多召聚合后凑不满 30 个 issue。
    chunk_results = self.vs.similarity_search_with_score(
        query, k=top_k * VECTOR_CHUNK_FETCH_MULTIPLIER, filter=filter_dict)

    issue_best = {}
    for doc, distance in chunk_results:
        issue_id = doc.metadata.get("issue_id")
        if not issue_id:
            continue
        score = 1 - float(distance)   # 只用于排序；现索引为 l2 遗留，数值含义不严格
        # 同一 issue 只保留最高分 chunk，body 用该 chunk 内容（= 与 query 最相关的片段）
        if issue_id not in issue_best or score > issue_best[issue_id]["score"]:
            issue_best[issue_id] = {"id": issue_id, "title": doc.metadata.get("title", ""),
                                    "body": doc.page_content, "score": score,
                                    "metadata": dict(doc.metadata)}
    return sorted(issue_best.values(), key=lambda x: -x["score"])[:top_k]
```

### 2.3 内层 RRF + docstore 补齐（`src/retrievers/hybrid_retriever.py`）

公式：`RRF(d) = Σ_每路 1/(k + rank_d)`，k=60。vector 第 1 名得 1/61，BM25 第 3 名
得 1/63，两路都出现则累加。

```python
rrf_scores, issue_docs = defaultdict(float), {}
for rank, doc in enumerate(vector_results, start=1):        # 第一遍：向量路
    rrf_scores[doc["id"]] += 1.0 / (RRF_K + rank)
    issue_docs[doc["id"]] = {"id": doc["id"], "title": doc.get("title", ""),
                             "body": doc.get("body", ""), "metadata": doc.get("metadata", {})}
for rank, doc in enumerate(bm25_results, start=1):          # 第二遍：BM25 路
    rrf_scores[doc["id"]] += 1.0 / (RRF_K + rank)
    if doc["id"] not in issue_docs:                         # BM25-only：先占位空正文
        issue_docs[doc["id"]] = {"id": doc["id"], "title": "", "body": "", "metadata": {}}

ranked_ids = sorted(rrf_scores, key=lambda i: -rrf_scores[i])[:top_k]
results = [dict(issue_docs[i], score=rrf_scores[i]) for i in ranked_ids]
self._hydrate(results)    # docstore 补齐：只给空 title/body 的候选填正文，不覆盖
```

`_hydrate` 与 docstore 的完整代码、以及外层 RRF（多 query 融合）的完整代码，
见 03a 决策 4 与 03b 决策 8 的内嵌代码块；逻辑要点：

- 外层 RRF 对"每条 query 的 Top-30 排名"再做一次同公式融合；
- 两路按 casefold 去重（改写=原文时只跑一路）；
- 同一 issue 在两路的正文完整度不同时，保留 title+body 更长的版本；
- 同分时 Python 稳定排序保证改写主路的结果排前。

## 自测答案

<details>
<summary>步骤 0-1 答案</summary>

1. 节点只返回自己产出的字段，LangGraph 做 dict 合并：新键加入、旧键覆盖。重试轮
   rewritten_query/keywords/component/retrieved_docs/reranked_docs/决策字段全部被
   新一轮覆盖；previous_decisions 是唯一追加的（Decision 节点 copy 后 append）。
2. `_parse_json` 返回 fallback：rewritten_query 直接用原始 issue、keywords 空、
   component None，流程继续走检索。不中断是因为改写只是增强，原文检索仍然可用，
   单点 LLM 故障不应打断整条链路。
3. 五项：RRF 融合后候选数、Reranker 输出候选数、缺 title/body 证据的候选数、
   最高 rerank 分、前两名分差。top_candidates 解决"模型只知道数字不知道内容"的
   问题——看到上轮检索回来的具体是什么，才能决定换方向还是补细节。
</details>

<details>
<summary>步骤 2 答案</summary>

4. Chroma 存的是 chunk，同一 issue 的多个 chunk 都可能命中并占名额；直接召 30 个
   chunk 聚合后可能只剩十几个 issue。先召 60 再聚合才能保证接近 30 个 issue 候选。
5. 等效于给这些词做词频加权（出现次数翻倍→BM25 的 TF 项增大），提升错误码/API 名
   这类精确信号的排名权重。向量路的输入仍是完整 query 句子，不拼 keywords，所以
   不受影响。
6. 内层 RRF 时是空字符串占位（BM25 索引只存 id）；融合排序完成后 `_hydrate` 从
   docstore 按 id 补齐；规则是"只填空、不覆盖"——向量路候选已有的最相关 chunk
   证据不能被正文开头覆盖。
</details>
