# 04 可复现控制

> 基于 00-随机性盘点的结论落成具体方案。目标不是"绝对可复现"（含 LLM 的系统
> 做不到），而是**"确定性部分严格复现，随机部分统计可复现，全部差异可归因"**。

## 1. 种子固定

| 随机操作 | 方案 |
| --- | --- |
| golden set family 打乱与划分 | `random.Random(EVAL_SEED)` 显式实例，EVAL_SEED=42 入 config；构建统计（含 seed）随 golden_set.json 落盘 |
| 评测抽样（--limit） | 同上（v2 现有实现已符合，见 01 文档内嵌代码） |
| 端到端重复实验的次序 | 重复轮 idx 作为记录字段；**不同 repeat 不换 seed**（采样集固定，随机性只来自 LLM），保证 n 次跑的是同一批 query |
| 任何新增随机操作 | 一律显式 `random.Random(seed)`；禁止裸 `random.xxx()` 和 `numpy.random` 全局态 |

## 2. LLM 节点设置

- **评测运行统一 temperature=0**（线上是 0.1；评测用 0 压方差）。两个口径都
  记进元数据，报告注明"评测口径 t=0"。
- max_tokens、prompt 版本（三个 .md 文件的内容 hash）进配置 hash。
- 每次 LLM 调用的**原始响应文本落盘**（trace 内），复盘时可以离线重放解析层
  而不再调 API。

## 3. temperature=0 为什么仍不能保证完全可复现（必须写进报告的免责说明）

1. **浮点非结合性 + 动态批处理**：服务端把你的请求和别人的请求拼成不同形状的
   batch，矩阵乘的求和顺序不同，logits 出现 1e-6 级差异；两个 token 概率本就
   接近时，argmax 会翻转，之后逐 token 级联放大。
2. **MoE 路由**：deepseek-chat 是混合专家架构，专家路由对数值扰动敏感，同一
   输入可能激活不同专家组合。
3. **服务端更新**：同一个模型名（deepseek-chat）背后的权重/推理引擎可能被
   服务商更新，API 不提供权重版本锁定；跨月的数字对比要带"模型可能已变"的
   注脚。
4. **无 seed 参数保证**：OpenAI 兼容接口的 seed 字段 DeepSeek 是否支持及其
   语义——待确认；即使支持，官方一般也只承诺"尽力而为"。
5. **项目自身的放大器**：confidence 横跨 0.7 阈值时，token 级微小差异被条件
   边放大成"是否多跑一整轮"的路径分叉（00 文档 2.2）。

结论：LLM 相关指标只报统计量（均值±标准差，n 次），单次数字不进结论。

## 4. 重复策略

| 对象 | 次数 | 报告口径 |
| --- | --- | --- |
| 纯检索层指标 | 1 次 | 点值（前提由断言 A2-7 守护：同输入两跑序列一致） |
| 端到端三分类/related 命中率/重试率 | n=3（预算够 n=5） | 均值 ± 样本标准差；同时给逐 repeat 明细表 |
| 判断"改动是否有效" | — | 差量 > 基线标准差×2 才视为信号；小于则标记"不显著，需加大 n 或样本" |
| 延迟 | 检索层 1 次（P50/P95）；LLM 层随端到端 n 次 | P50/P95；LLM 层另附均值±标准差 |

## 5. 运行元数据（每次 run 必录）

```text
run_id            : 时间戳+短随机后缀（仅作标识，不影响实验）
timestamp         : ISO8601
git_commit        : 代码版本（v1/v2 各自仓库的 HEAD）
repo_variant      : "v1" | "v2"
config_hash       : sha256(排序后的全部 config 项 + 3 个 prompt 文件内容)
dataset_hash      : 数据快照文件 sha256
index_manifest    : {chroma_dir 名, chroma 构建批次标识, bm25.pkl sha256,
                     bm25_chunk.pkl sha256(消融用), docstore.pkl sha256}
golden_set_hash   : golden_set.json sha256（含其内嵌 build_stats/seed）
eval_seed         : 42
sample_limit      : 200 / null(全量)
llm               : {provider, model 名, temperature, max_tokens}
env               : {python 版本, torch/sentence-transformers/rank_bm25/langgraph
                     版本, OMP_NUM_THREADS, 机器标识}
variant           : 消融变体名（03 文档命名表）
repeat_idx        : 0..n-1（端到端）
```

**可比性规则**：两次运行可直接比 ⇔ dataset_hash、index_manifest、
golden_set_hash、eval_seed、sample_limit 全部一致；config_hash 或 git_commit
不同 = 这就是被测变量。任何 hash 不一致的对比必须在报告里显式声明差异项。

## 6. v1 / v2 特别事项

- v1 跑评测前置：每个配置深拷贝候选（v1 Reranker 原地写分数，00 文档 2.3）；
  共享 v2 资产时 index_manifest 记 v2 的资产 hash 并在 repo_variant=v1 的
  记录里注明"资产借自 v2"。
- 索引重建 = 断代：HNSW 建图有随机性（00 文档），重建 chroma 后
  index_manifest 变化，跨批次向量路数字不做精细对比（只做趋势判断）。
- 冒烟评测（50 条）进 CI 的话，机器变了 env 字段变——CI 机器与本地数字
  **分池存放**，不混合出报告。
