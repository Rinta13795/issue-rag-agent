## 2. 模块与函数规格

### suite/meta.py

```text
collect_meta(variant: str, repeat_idx: int | None) -> dict
  # 返回 04 文档第 5 节的全部字段；内部函数：
  file_sha256(path) -> str
  config_hash() -> str          # 全部 config 常量排序序列化 + 3 个 prompt 文件内容
  env_info() -> dict            # python/依赖版本、OMP_NUM_THREADS、平台
```

### suite/variants.py

```text
VARIANTS: dict[str, VariantSpec]
  # VariantSpec 是 dataclass：
  #   name: str                     # 03 文档命名表，如 "hyb_asym_rr"
  #   mode: "retrieval" | "e2e"    # 决定跑一次还是重复
  #   description: str
  #   overrides: dict               # 对 config 的差量，如 {"MAX_RETRIES": 0}
  #   retriever_factory: str        # 构建检索器的策略名："vector"/"hyb_sym"/...
get_variant(name) -> VariantSpec   # 未知名报错并列出可用项
```

### suite/chunk_bm25.py（消融②）

```text
build_chunk_bm25(issues: list[dict], out_path: str) -> None
  # 语料 = chunk_issue() 输出的每个 chunk 的 page_content 分词
  # 持久化 {"bm25": BM25Okapi, "chunk_issue_ids": list[str]}  # 下标对齐
search_chunk_bm25(index, query: str, top_k: int) -> list[dict]
  # get_scores -> chunk 排名 -> 按 issue_id 取每 issue 最高分 -> Top-K issue
  # 返回 [{"id": issue_id, "score": float}]，接口与现有 BM25Retriever.search 对齐
```

### suite/assertions.py

```text
assert_output_contract(result: dict, reranked_ids: set[str]) -> list[str]
  # 执行 A1-1..A1-7，返回违例描述列表（空=通过）；不抛异常，由调用方汇总
assert_pipeline_invariants(state: dict) -> list[str]      # A2-1..A2-6
assert_retrieval_deterministic(retriever, query: str) -> list[str]   # A2-7 两跑比对
assert_golden_set(golden_path: str, indexed_ids: set[str]) -> list[str]  # A3
```

### suite/runner.py

```text
run_retrieval_variant(spec, queries, assets) -> list[QueryRecord]
  # 每条 query：检索(+可选精排) -> 剔自命中 -> compute_all(cutoffs 按模式)
  # 同时执行 A2 断言；QueryRecord 含 query_id/retrieved_ids/metrics/latency/violations
run_e2e_variant(spec, queries, assets, repeat_idx) -> list[QueryRecord]
  # 每条 query：run_agent 全流程 -> A1 断言 -> 三分类比对人工标注 ->
  # 记录 decision/confidence/related/retry_count/token 用量/LLM 原始响应引用
  # 候选一律深拷贝后传入（v1 兼容，00 文档 2.3）
aggregate(records) -> dict     # 均值指标 + P50/P95 + 违例计数
```

### suite/repeat.py

```text
run_with_repeats(spec, queries, assets, n: int) -> RepeatSummary
  # 循环调 run_e2e_variant(repeat_idx=0..n-1)
  # RepeatSummary: 每指标 {mean, std, per_repeat: [..]}；重试率/fallback 率同格式
significance_flag(delta: float, baseline_std: float) -> str
  # 返回 "signal"（|delta| > 2*std）/ "noise"
```

### suite/store.py

```text
append_run(meta: dict, summary: dict, path="results/runs.jsonl") -> str  # 返回 run_id
save_raw(run_id, records, llm_responses) -> None       # results/raw/<run_id>/
load_runs(filters: dict) -> list[dict]                  # 按 variant/日期/hash 过滤
```

### 结果表结构（runs.jsonl 每行字段）

```text
run_id, timestamp, repo_variant(v1/v2), variant, mode, repeat_idx,
git_commit, config_hash, dataset_hash, golden_set_hash, index_manifest{...},
eval_seed, sample_limit, llm{model,temperature},
metrics{recall@5,recall@10,recall@30?,precision@5,mrr,ndcg@10,
        e2e_accuracy?, confusion{..}?, related_hit_rate?,
        retry_rate?, fallback_rate?, p50_latency, p95_latency,
        input_tokens?, output_tokens?},
assertion_violations{A1_1: int, ..., total: int},
notes
```

设计要点：一行自足（含全部可比性 hash），任何两行都能独立判断"可不可以比"；
问号字段按 mode 缺省为 null。

```text
render_ablation_chain() -> str
```

### suite/cli.py（命令行契约）

```text
python -m eval.suite run --variant hyb_asym --limit 200
python -m eval.suite run --variant d1_noretry --mode e2e --repeats 3
python -m eval.suite run-chain            # 主消融链①②③④连跑（检索层）
python -m eval.suite assert-all           # A3 资产断言 + A2-7 确定性回归
python -m eval.suite report --variants v_only,hyb_sym,hyb_asym,hyb_asym_rr \
                            --by length
python -m eval.suite compare <run_id_a> <run_id_b>
python -m eval.suite baseline set --variant hyb_asym_rr --run <run_id>

# 一条命令跑完全套（检索层全链 + 断言 + 报告；端到端需 --with-e2e 显式开启，
# 因为要花 LLM 费用）：
python -m eval.suite all [--with-e2e --repeats 3] [--limit 200] [--out results/]
```

参数规则：--variant 必须在 variants.py 注册表内；--repeats 只对 e2e 生效，
对 retrieval 模式传入即报错（防止误以为检索层需要重复）；所有命令结束时打印
run_id 与结果文件路径。

## 3. 执行顺序建议（首次跑通）

1. `assert-all`（资产与确定性前提）→ 2. `run-chain`（主消融链，检索层）→
3. `report --variants ...`（出 ①②③④ 递进表）→ 4. 充值/换 key 后
`run --variant hyb_asym_rr --mode e2e --repeats 3`（端到端基线）→
5. 逐个诊断组 D1-D8。

## 4. v1 口径

v1 跑法：`--repo-variant v1` 让 runner 从 v1 代码路径 import（sys.path 切换），
资产用 v2 共享（meta 里注明）；仅支持与 v1 能力对齐的变体（无 docstore/校验
类变体）。⚠️ 待确认：v1 与 v2 的 Python 依赖版本是否完全一致——不一致时在
env 字段体现，报告须注明。
