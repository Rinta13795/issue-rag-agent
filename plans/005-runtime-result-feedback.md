# 待处理：完成反馈被错误回复为“证据不足”

状态：已实施最终回答兼容、输出错误分类、解决反馈的记忆范围保护；普通文本和格式异常均有回归测试。

## 复现场景与已核对依据

2026-09-30 用户在 INFO 日志问题的调查中说“OK我解决了”。页面显示“本轮没有得到足够证据，请补充线索后继续调查”。

已读取本地会话中这一轮保存的模型原始结果：模型实际返回“好的，问题解决了就行。简单收个尾：……”等正常中文，结束原因为 `stop`，没有返回约定的 JSON。页面出现的“证据不足”来自程序兜底，不是模型对问题的判断。

调用链：

1. `src/chat/runtime.py` 要求最终回答使用 JSON，但模型可能直接返回自然语言。
2. `src/chat/context.py` 的 `parse_json_object` 遇到非 JSON 会返回空字典，不抛异常。
3. Runtime 使用异常分支接管纯文本，因此这次没有进入文本回退。
4. 读取不到 `answer` 后，Runtime 显示固定的“证据不足”文案，覆盖了模型实际回复。

这是回答协议兼容处理的缺陷。结构解析失败不表示调查证据不足。

## 后续修改方案

### 1. 分清回答格式异常与证据判断

在 Runtime 最终输出入口显式检查解析结果，不依赖解析器抛异常。

- 有合法、非空 `answer`：使用结构化回答，继续校验引用。
- 返回正常自然语言：保留文本回答；不凭空补引用，不增加额外模型调用。
- 返回空内容、错误结构、截断 JSON 或只有工具调用却无最终内容：按具体原因提示本轮回答未完整生成，保留已取得证据与可重试状态。
- “证据不足”只用于有实际调查依据的判断，不能当格式解析失败的通用兜底。
- 保存最终输出处理方式与失败原因，便于定位真实模型与离线替身的差异。

### 2. 接受用户的解决反馈，正确结束本次调查

Runtime 提示词明确处理“解决了”“有效”“还是不行”等反馈：接续当前案例，回应结果，不自动把用户送回调查入口。

“OK我解决了”足以记录“用户报告当前问题已解决”，但不足以判断用户采用了哪种方案。本例前文既有 PR，也有临时处理建议，不能直接认定用户应用 PR #359 后验证成功。

- 当前案例记录用户报告的问题结果，来源引用本轮用户原话。
- 具体采用的方法、修改版本与根因仍可未知，不能顺手补全。
- 若用户明确说“用了刚才那个补丁，有效”，再把对应方案修订为用户确认有效。
- 若需要完善经验，可以自然地问一句“最后用的是哪个办法？”；允许用户不补充，不阻止保存已知结果，不强迫继续调查。
- 解决状态与方案条目的验证状态分开表达；未确认的 PR/假设保留原状态和修订历史。

### 3. 与后台自动记忆衔接

后台快照应使用实际展示的回答与用户反馈，避免把格式兜底错误写进案例摘要。

本次原始用户反馈仍已保存，因此不能仅凭错误回复判断自动记忆没有写入。实施时核对这轮整理任务、案例摘要和来源记录；如果已有错误总结，按新证据修订，保留历史，不批量重加工其他对话。

完成反馈写入案例结果后，界面可以呈现“用户报告已解决；采用方法未说明”。不得宣称“PR 修复已在用户环境验证”或“官方版本已修复”。

## 验收用例

- 模型返回纯文本“好的，问题解决了”：界面保留回复，不出现“证据不足”。
- 合法 JSON 回复：回答和引用校验保持正常。
- 空输出、截断 JSON、缺少回答字段：提示正确原因，不伪造调查结论或引用。
- 前文提供两种方案，用户仅说“解决了”：自动保存问题结果，不任选一种方案升级为已验证。
- 用户明确说用了某个方案有效或失败：更新对应条目并保留来源、修订历史。
- 后台整理失败：用户已看到的回应不改变，用户反馈仍保留。
- 使用与本次真实返回相同的纯文本响应增加回归测试；既有 Issue→PR、提问恢复、预算和草稿测试继续通过。
