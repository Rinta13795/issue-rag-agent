# Plan 003：让 Agent 积累、检索并迭代排查经验

## 目标

把一次问题处理留下的证据和过程保存下来，之后遇到相关问题时能够找回。允许先记录尚不完整的案例，再根据使用反馈补充、修正或归档；单次案例不会自动升级成所有仓库通用的规则。

## 设计依据

参考通用 Agent 记忆设计中的三个机制：

1. **按记忆类型分工**：LangMem 将长期记忆区分为事实知识（semantic）、过往经历（episodic）和可执行的行为/步骤（procedural）。本项目的核心首先是 episodic：一次具体问题如何被定位和解决；以后才从多个案例提炼 semantic 知识或 procedural 排查步骤。
2. **记忆有写入和读取两条流程**：LangGraph 将单个 thread 的检查点与跨 thread 的 Store 分开；Mem0 将长期记忆拆成提取/去重/更新/删除，以及按问题检索。借鉴这套生命周期，不要求引入对应框架或服务。
3. **区分常驻信息与按需检索的档案**：Letta 的小型 memory blocks 用于始终需要的偏好和约束，archival memory 用于大量、按需检索的记录。项目里的个人偏好可以少量常驻；排查案例应作为可检索档案，避免每轮把所有历史塞进上下文。

参考： [LangMem 记忆概念](https://langchain-ai.github.io/langmem/concepts/conceptual_guide/) · [LangGraph Store](https://docs.langchain.com/oss/python/langgraph/stores) · [Mem0 工作机制](https://docs.mem0.ai/core-concepts/how-it-works) · [Letta Memory Blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks)

## 初步模型：案例先存，经验后提炼

### 1. 案例记忆（episodic，第一优先）

每次排查都可以先保存为一条案例，未完成时也能保存。最低限度包含：

- 问题现象、仓库/项目和时间
- 排查过程与关键证据链接（Issue、PR、文件或讨论）
- 当前结论和状态：待验证、已解决、未解决或被推翻
- 根因与解决方案；不确定内容显式标为假设
- 用户自己的复盘或启发、适用条件和限制

经验正文先允许自然语言，不急着冻结字段。来源、状态、仓库范围等检索与可信度需要的信息应可单独识别。

### 2. 可复用知识（semantic，后续提炼）

从已确认案例中整理稳定事实，例如某版本的行为变化、某组件的常见故障特征。每条知识保留支撑它的案例来源；新案例冲突时标记需要复核，不能悄悄覆盖旧结论。

### 3. 排查方法（procedural，后续提炼）

当相同排查步骤在多个案例中重复有效，或由用户明确总结后，再整理成可执行的检查清单/Skill。步骤应带适用条件、依据案例和失败边界。

## 生命周期

```text
捕获一次排查 → 保存为案例（允许不完整） → 用户补充/确认/修正
                                      ↓
                          后续按问题检索相关案例
                                      ↓
                 多次验证或用户总结 → 提炼成知识/步骤
```

- **写入**：初期由用户显式保存或确认，模型只负责整理草稿；之后可讨论自动生成待审草稿。保留来源链接与确认状态。
- **检索**：按用户/仓库范围、问题文本和证据元数据检索；关键词负责错误码、版本号和符号等精确匹配，语义检索负责不同说法，按需融合排序。先展示来源和状态，再让模型基于被取回的记录回答。
- **复用**：同仓库的已确认案例优先；跨仓库记录标成参考案例，显示相似点、差异和适用条件，不把“搜到”说成“可直接套用”。
- **修订与遗忘**：允许补充、纠错、合并重复案例和删除；修订保留来源关系，避免失效经验继续被当成现行结论。
- **提炼**：只有有足够证据或用户明确总结时，才把单次案例提升为通用知识或排查步骤；提升后的内容回链到原案例。

## 与当前实现的关系

当前已有短期会话 SQLite、独立长期记忆 SQLite、用户确认、删除和少量记忆注入。长期记忆现阶段只有偏好/经验短文本，原文摘录校验较简单，经验召回使用字符二元组相似度。它适合作为“记忆持久化”的原型，不足以支撑带来源、状态、证据、适用范围的案例库。

后续可沿用“独立持久化、用户可控”的原则，逐步把经验记录升级为案例档案，并增加合适的关键词/语义混合检索；不必因此替换 LangGraph 或一次引入新的记忆框架。

## 暂不定案的问题

- 用户案例、公开 GitHub 案例和通用知识之间的存储/权限边界。
- 多个案例冲突时的排序、过期与失效规则。
- 跨项目经验的可迁移性如何呈现和评估。
- 何时自动生成待确认记录，何时由用户主动保存。

先用真实案例验证记录模板和检索是否有用，再决定这些规则及数据结构。
